# Music Manager 프로젝트 - 현재 문제점 분석

## 문제 요약

**증상**: Docker로 백엔드/프론트엔드를 올려도 음악 파일에 대한 명세(메타데이터)를 조회할 수 없음. Plex나 Navidrome처럼 음악 라이브러리의 앨범, 트랙, 아티스트 정보를 볼 수 없음.

**분석 일자**: 2025-11-10

---

## 근본 원인 분석

### 🔴 주요 문제 1: Docker 환경변수 경로 불일치

**위치**: `docker-compose.yml` (라인 14-15)

```yaml
environment:
  - DATABASE_URL=sqlite:///./music_manager.db
  - MUSIC_LIBRARY_PATH=/music          # ❌ 잘못된 경로
  - FILE_BROWSER_ROOT_PATH=/mnt/nas-music  # ✅ 올바른 경로
```

```yaml
volumes:
  - ./backend:/app
  - /mnt/nas-music:/mnt/nas-music:ro   # ✅ 실제 마운트 경로
```

**문제점**:
- 환경변수 `MUSIC_LIBRARY_PATH`가 `/music`으로 설정되어 있음
- 하지만 실제 볼륨은 `/mnt/nas-music`으로 마운트됨
- 백엔드가 `/music` 경로에서 음악 파일을 찾으려 하지만 해당 경로가 존재하지 않음
- **결과**: 음악 파일 스캔 실패, 데이터베이스에 데이터 없음

**영향 범위**:
- `FileScannerService` (`backend/app/services/file_scanner_service.py:47`)
  - `library_path`를 받아서 음악 파일 스캔
  - 잘못된 경로로 인해 파일을 찾지 못함
- 초기 스캔 스크립트들
  - `scripts/scan_music_library.py`
  - `scripts/initial_scan.py`
  - 모두 `settings.music_library_path`를 사용

---

### 🟡 주요 문제 2: 초기 스캔 미실행 가능성

**관련 파일**:
- `backend/scripts/scan_music_library.py`
- `backend/scripts/initial_scan.py`
- `backend/scripts/full_setup.py`

**문제점**:
- Docker 컨테이너가 시작될 때 자동으로 음악 라이브러리 스캔이 실행되지 않음
- `docker-compose.yml`의 command가 단순히 FastAPI 서버만 실행:
  ```yaml
  command: uvicorn main:app --host 0.0.0.0 --port 8000 --reload
  ```
- 초기 스캔을 수동으로 실행해야 하지만, 경로 문제로 인해 실행해도 실패할 것

**결과**:
- 데이터베이스(SQLite: `music_manager.db`)가 비어있음
- 트랙, 앨범, 아티스트 테이블에 데이터 없음
- API 요청 시 빈 결과만 반환

---

### 🟢 정상 작동하는 부분

**파일 브라우저 기능**:
- 환경변수: `FILE_BROWSER_ROOT_PATH=/mnt/nas-music` (올바름)
- 파일 시스템에 직접 접근하므로 정상 작동
- API 엔드포인트: `/api/v1/files/browse`
- 파일 탐색, 이름 변경, MP3 태그 편집 등은 작동할 것으로 예상

**프론트엔드-백엔드 통신**:
- Vite 프록시 설정이 올바름 (`vite.config.ts:25-42`)
- Docker 환경에서 `music-manager-backend:8000`로 프록시
- 네트워크 설정 정상 (`music-manager-network`)

```python

    database_url: str = "sqlite:///./music_manager.db"
    music_library_path: Path = Path("/mnt/nas-music")  # 기본값은 올바름
```

- **기본값은 올바르게 설정됨**: `/mnt/nas-music`

- Pydantic Settings는 환경변수를 대문자로 변환하여 매칭
  - `MUSIC_LIBRARY_PATH` → `music_library_path`

## 데이터 흐름 분석

### 정상적인 경우:

```
1. Docker 컨테이너 시작
   ↓
2. 초기 스캔 실행 (scripts/scan_music_library.py)
   ↓
3. FileScannerService가 /mnt/nas-music 탐색
   ↓
4. 음악 파일 메타데이터 추출 (mutagen 라이브러리)
   ↓
5. SQLite DB에 저장 (Track, Album, Artist 테이블)
   ↓
6. 프론트엔드에서 API 호출 (/api/v1/tracks, /api/v1/albums)
   ↓
7. 음악 라이브러리 조회 가능 ✅
```

### 현재 상황:

```
1. Docker 컨테이너 시작 ✅
   ↓
2. 초기 스캔 실행 안됨 또는 잘못된 경로로 실행 ❌
   ↓
3. FileScannerService가 /music 탐색 (존재하지 않음) ❌
   ↓
4. 파일을 찾지 못함 ❌
   ↓
5. SQLite DB 비어있음 ❌
   ↓
6. 프론트엔드에서 API 호출
   ↓
7. 빈 결과만 반환 ([] 또는 count: 0) ❌
```

## 해결 방법

### 🔧 즉시 해결 방법 (Quick Fix)

**1단계**: `docker-compose.yml` 수정

```yaml
environment:
  - DATABASE_URL=sqlite:///./music_manager.db
  - MUSIC_LIBRARY_PATH=/mnt/nas-music  # ✅ 수정: /music → /mnt/nas-music
  - FILE_BROWSER_ROOT_PATH=/mnt/nas-music
```

**2단계**: 컨테이너 재시작

```bash
docker-compose down
docker-compose up -d
```

**3단계**: 초기 스캔 실행

```bash
# 백엔드 컨테이너 내부에서 실행
docker exec -it music-manager-backend python scripts/scan_music_library.py

# 또는 full_setup.py 실행 (DB 초기화 + 스캔)
docker exec -it music-manager-backend python scripts/full_setup.py
```

**4단계**: 스캔 진행 상황 모니터링

```bash
# 로그 확인
docker logs -f music-manager-backend

# 데이터베이스 확인
docker exec -it music-manager-backend sqlite3 music_manager.db "SELECT COUNT(*) FROM tracks;"
```

### 🏗️ 장기 해결 방법 (Best Practice)

**1. 자동 스캔 설정**

`docker-compose.yml`에 초기화 스크립트 추가:

```yaml
music-manager-backend:
  # ... 기존 설정 ...
  entrypoint: ["/bin/sh", "-c"]
  command:
    - |
      echo "Checking database initialization..."
      if [ ! -f /app/music_manager.db ]; then
        echo "First run detected, initializing database and scanning library..."
        python scripts/full_setup.py
      fi
      echo "Starting FastAPI server..."
      uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

**2. 환경변수를 .env 파일로 관리**

`.env` 파일 생성:
```bash
DATABASE_URL=sqlite:///./music_manager.db
MUSIC_LIBRARY_PATH=/mnt/nas-music
FILE_BROWSER_ROOT_PATH=/mnt/nas-music
SECRET_KEY=change-me-in-production
```

`docker-compose.yml`:
```yaml
music-manager-backend:
  env_file:
    - .env
  # environment 섹션 제거 또는 오버라이드만 남김
```

**3. 헬스 체크 추가**

```yaml
music-manager-backend:
  healthcheck:
    test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
    interval: 30s
    timeout: 10s
    retries: 3
    start_period: 40s
```

**4. 볼륨 권한 확인**

## 추가 고려사항

### 성능 이슈

- **대용량 라이브러리**: 수천~수만 개의 파일이 있는 경우
  - 첫 스캔에 시간이 오래 걸림 (수 시간)
  - 배치 커밋 사용 (현재: 100개씩)
  - 로그로 진행 상황 확인 필요

### 파일 권한 문제

- SSHFS로 마운트된 경우 권한 문제 발생 가능
- Docker 컨테이너 사용자와 파일 소유자가 다를 수 있음
- 읽기 전용(`:ro`) 마운트 권장

### 증분 스캔

- 현재는 기존 파일 스킵 (`file_path` 체크)
- 새 파일만 스캔하므로 재실행 시 빠름
- 하지만 파일이 이동/변경된 경우 감지 못함
- 향후 `library_watcher.py` 활용 가능
