# 음악 파일 조회 문제 진단 가이드

## 문제 개요

Docker 환경에서 백엔드/프론트엔드를 실행했을 때 음악 파일에 대한 명세 조회가 정상적으로 작동하지 않는 문제

## 진단 체크리스트

### 1. Docker 볼륨 마운트 확인

#### 1.1 볼륨 설정 검증
```bash
# docker-compose.yml 확인
cat docker-compose.yml | grep -A 10 volumes

# 실행 중인 컨테이너의 볼륨 확인
docker inspect <container_name> | grep -A 20 Mounts
```

**체크 포인트:**
- [ ] 음악 파일 디렉토리가 올바르게 마운트되어 있는가?
- [ ] 호스트 경로와 컨테이너 경로가 정확한가?
- [ ] 볼륨 권한이 올바르게 설정되어 있는가? (읽기 권한)

#### 1.2 파일 접근성 확인
```bash
# 컨테이너 내부에서 파일 확인
docker exec -it <backend_container> ls -la /path/to/music/files

# 파일 권한 확인
docker exec -it <backend_container> stat /path/to/music/files
```

**주요 문제:**
- 파일이 마운트되지 않음
- 권한 문제 (permission denied)
- 경로 불일치

---

### 2. 백엔드 API 확인

#### 2.1 API 엔드포인트 동작 확인
```bash
# 음악 파일 목록 API 테스트
curl -X GET http://localhost:<backend_port>/api/music/files

# 특정 음악 파일 정보 조회
curl -X GET http://localhost:<backend_port>/api/music/files/<file_id>

# API 헬스 체크
curl -X GET http://localhost:<backend_port>/health
```

**체크 포인트:**
- [ ] API 서버가 정상적으로 실행되고 있는가?
- [ ] 엔드포인트가 응답하는가?
- [ ] 응답 상태 코드가 정상인가? (200 OK)
- [ ] 응답 데이터 형식이 올바른가?

#### 2.2 백엔드 로그 확인
```bash
# 백엔드 컨테이너 로그 확인
docker logs <backend_container> --tail=100 -f

# 에러 로그 필터링
docker logs <backend_container> 2>&1 | grep -i error
```

**주요 에러 패턴:**
- 데이터베이스 연결 실패
- 파일 시스템 접근 오류
- 메타데이터 파싱 오류
- ORM/쿼리 실패

---

### 3. 데이터베이스 확인

#### 3.1 데이터베이스 연결 확인
```bash
# DB 컨테이너 상태 확인
docker ps | grep database

# DB 연결 테스트
docker exec -it <db_container> psql -U <username> -d <database_name>
# 또는 MySQL의 경우
docker exec -it <db_container> mysql -u <username> -p <database_name>
```

**체크 포인트:**
- [ ] 데이터베이스 컨테이너가 실행 중인가?
- [ ] 백엔드에서 DB에 연결할 수 있는가?
- [ ] 네트워크 설정이 올바른가?

#### 3.2 음악 파일 메타데이터 확인
```sql
-- 음악 파일 테이블 확인
SELECT * FROM music_files LIMIT 10;

-- 테이블 스키마 확인
\d music_files  -- PostgreSQL
DESCRIBE music_files;  -- MySQL

-- 레코드 수 확인
SELECT COUNT(*) FROM music_files;
```

**주요 문제:**
- 테이블이 존재하지 않음
- 데이터가 비어있음
- 스키마 마이그레이션 미완료
- 파일 경로가 잘못 저장됨

---

### 4. 프론트엔드 확인

#### 4.1 API 호출 확인
**브라우저 개발자 도구 확인:**
- Network 탭에서 API 요청 확인
- Console에서 JavaScript 에러 확인

**체크 포인트:**
- [ ] API 요청이 올바른 URL로 전송되는가?
- [ ] CORS 에러가 발생하지 않는가?
- [ ] 응답 데이터를 올바르게 파싱하는가?
- [ ] 렌더링 로직이 정상적으로 작동하는가?

#### 4.2 환경 변수 확인
```bash
# 프론트엔드 환경 변수 확인
docker exec -it <frontend_container> env | grep API
```

**주요 설정:**
- API_URL 또는 BACKEND_URL
- API_BASE_PATH
- 포트 설정

### 5. 네트워크 확인

#### 5.1 컨테이너 간 통신 확인
```bash
# Docker 네트워크 목록
docker network ls

# 네트워크 상세 정보
docker network inspect <network_name>

# 컨테이너에서 다른 컨테이너로 ping
docker exec -it <frontend_container> ping <backend_container>

# 포트 접근성 확인
docker exec -it <frontend_container> curl http://<backend_container>:<port>/health
```

**체크 포인트:**
- [ ] 모든 컨테이너가 같은 네트워크에 있는가?
- [ ] 서비스 이름으로 통신할 수 있는가?
- [ ] 포트가 올바르게 노출되어 있는가?

### 6. 파일 메타데이터 추출 확인

#### 6.1 메타데이터 라이브러리 확인
**일반적으로 사용되는 라이브러리:**
- Python: mutagen, tinytag, eyed3
- Node.js: music-metadata, node-id3
- Go: taglib-go

**테스트 방법:**
```bash
# 컨테이너 내부에서 테스트 스크립트 실행
docker exec -it <backend_container> python -c "
from mutagen import File
audio = File('/path/to/music/file.mp3')
print(audio.info)
print(audio.tags)
"
```

**주요 문제:**
- 라이브러리가 설치되지 않음
- 지원하지 않는 파일 형식
- 손상된 파일
- 인코딩 문제

## 일반적인 문제 및 해결 방안

### 문제 1: 음악 파일이 마운트되지 않음

**원인:**
- docker-compose.yml의 볼륨 설정 오류
- 상대 경로 사용으로 인한 경로 불일치

**해결 방안:**
```yaml
# docker-compose.yml
services:
  backend:
    volumes:
      - /absolute/path/to/music:/app/music:ro  # 절대 경로 사용, 읽기 전용
```

### 문제 2: 데이터베이스에 음악 파일 정보가 없음

**원인:**
- 초기 스캔/인덱싱이 실행되지 않음
- 마이그레이션 미실행

**해결 방안:**
```bash
# 마이그레이션 실행
docker exec -it <backend_container> npm run migrate
# 또는
docker exec -it <backend_container> python manage.py migrate

# 음악 파일 스캔/인덱싱 실행
docker exec -it <backend_container> npm run scan
# 또는
docker exec -it <backend_container> python manage.py scan_music
```

### 문제 3: CORS 에러

**원인:**
- 백엔드에서 프론트엔드 origin을 허용하지 않음

**해결 방안:**
```javascript
// Express.js 예시
app.use(cors({
  origin: process.env.FRONTEND_URL || 'http://localhost:3000',
  credentials: true
}));
```

### 문제 4: 환경 변수 불일치

**원인:**
- .env 파일이 컨테이너에 전달되지 않음
- 환경 변수명 불일치

**해결 방안:**
```yaml
# docker-compose.yml
services:
  backend:
    env_file:
      - .env
    environment:
      - NODE_ENV=production
      - DB_HOST=database
      - DB_PORT=5432
```

### 문제 5: 파일 권한 문제

**원인:**
- 컨테이너 사용자가 파일에 접근할 권한이 없음

**해결 방안:**
```bash
# 호스트에서 권한 수정
chmod -R 755 /path/to/music/files

# 또는 docker-compose.yml에서 사용자 설정
services:
  backend:
    user: "${UID}:${GID}"
```

## 진단 순서

1. **Docker 컨테이너 상태 확인** → 모든 컨테이너가 실행 중인지 확인
2. **볼륨 마운트 확인** → 파일이 컨테이너 내부에서 보이는지 확인
3. **데이터베이스 확인** → DB 연결 및 데이터 존재 여부 확인
4. **백엔드 API 확인** → API가 정상 응답하는지 확인
5. **네트워크 확인** → 컨테이너 간 통신 확인
6. **프론트엔드 확인** → API 호출 및 렌더링 확인
7. **로그 분석** → 모든 컨테이너의 로그에서 에러 찾기
