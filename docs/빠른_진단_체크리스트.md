# Music Manager - 빠른 진단 체크리스트

음악 파일 조회가 안될 때 5분 안에 문제를 파악하기 위한 체크리스트

---

## ⚡ 1단계: 컨테이너 상태 확인 (30초)

```bash
docker ps -a | grep music-manager
```

**확인 사항:**
- [ ] 모든 컨테이너가 `Up` 상태인가?
- [ ] 컨테이너가 재시작을 반복하지 않는가?
- [ ] 백엔드: `music-manager-backend`
- [ ] 프론트엔드: `music-manager-frontend`

**문제가 있다면:**
```bash
# 로그 확인
docker logs music-manager-backend --tail=50
docker logs music-manager-frontend --tail=50
```

---

## ⚡ 2단계: API 접근성 확인 (30초)

```bash
# 헬스 체크
curl http://localhost:32000/api/v1/health

# 라이브러리 통계 확인
curl http://localhost:32000/api/v1/library/stats
```

**예상 결과:**
```json
{
  "total_tracks": 980,
  "total_albums": 120,
  "total_artists": 85
}
```

**만약 모두 0이면:** 데이터베이스에 데이터가 없음 → 3단계로

**만약 연결 실패:** 백엔드 문제 → 1단계 로그 확인

---

## ⚡ 3단계: 데이터베이스 확인 (1분)

```bash
# DB 파일 존재 확인
docker exec music-manager-backend ls -lh music_manager.db

# 레코드 수 확인
docker exec music-manager-backend sqlite3 music_manager.db "
SELECT
  (SELECT COUNT(*) FROM tracks) as tracks,
  (SELECT COUNT(*) FROM albums) as albums,
  (SELECT COUNT(*) FROM artists) as artists;
"
```

**결과 분석:**
- **파일 없음**: DB가 생성되지 않음 → 5단계(초기화)로
- **모두 0**: 스캔이 안됨 → 4단계로
- **데이터 있음**: 다른 문제 → 로그 확인

---

## ⚡ 4단계: 볼륨 마운트 확인 (1분)

```bash
# 음악 파일 디렉토리 확인
docker exec music-manager-backend ls -la /mnt/nas-music | head -20

# 음악 파일 개수 확인
docker exec music-manager-backend find /mnt/nas-music -type f \( -name "*.mp3" -o -name "*.flac" \) | wc -l
```

**확인 사항:**
- [ ] 디렉토리가 존재하는가?
- [ ] 음악 파일이 보이는가?
- [ ] 파일 권한이 읽기 가능한가?

**문제가 있다면:**
- 호스트에서 마운트 확인: `ls -la /mnt/nas-music`
- `docker-compose.yml`의 volumes 설정 확인

---

## ⚡ 5단계: 환경변수 확인 (30초)

```bash
docker exec music-manager-backend env | grep -E "MUSIC_LIBRARY_PATH|FILE_BROWSER"
```

**올바른 설정:**
```
MUSIC_LIBRARY_PATH=/mnt/nas-music
FILE_BROWSER_ROOT_PATH=/mnt/nas-music
```

**❌ 잘못된 설정:**
```
MUSIC_LIBRARY_PATH=/music  # 이것이 현재 문제!
```

**수정 방법:**
1. `docker-compose.yml` 수정
2. `docker-compose down && docker-compose up -d`

---

## ⚡ 6단계: 스캔 실행 상태 확인 (1분)

```bash
# 로그에서 스캔 관련 메시지 검색
docker logs music-manager-backend 2>&1 | grep -i "scan\|processed\|created"
```

**스캔 성공 시 로그 예시:**
```
🎵 Processing files...
📂 Processed 50 files... (Created: 45, Updated: 0, Skipped: 5)
📂 Processed 100 files... (Created: 95, Updated: 0, Skipped: 5)
✅ Scan completed
```

**스캔 실행 안됨:** 6단계로

## 🔧 빠른 해결 방법

### 시나리오 A: 환경변수 문제 (가장 흔한 경우)

**문제**: `MUSIC_LIBRARY_PATH=/music`

**해결**:
```bash
# 1. docker-compose.yml 수정
vi docker-compose.yml
# MUSIC_LIBRARY_PATH를 /music에서 /mnt/nas-music으로 변경

# 2. 재시작
docker-compose down
docker-compose up -d

# 3. 스캔 실행
docker exec music-manager-backend python scripts/scan_music_library.py
```

**예상 시간**: 5분 + 스캔 시간

---

### 시나리오 B: 스캔 미실행

**문제**: DB는 있지만 데이터가 없음

**해결**:
```bash
# 전체 초기화 및 스캔
docker exec -it music-manager-backend python scripts/full_setup.py

# 또는 스캔만
docker exec -it music-manager-backend python scripts/scan_music_library.py
```

**진행 상황 모니터링**:
```bash
# 다른 터미널에서 로그 실시간 확인
docker logs -f music-manager-backend
```

**예상 시간**:
- 소규모 (100곡): 1-2분
- 중규모 (1,000곡): 5-10분
- 대규모 (10,000곡): 30분-1시간

---

### 시나리오 C: 볼륨 마운트 문제

**문제**: `/mnt/nas-music`이 컨테이너에서 안보임

**해결**:
```bash
# 1. 호스트에서 확인
ls -la /mnt/nas-music

# 2. 마운트 상태 확인 (SSHFS 등)
mount | grep nas-music

# 3. Docker 볼륨 재마운트
docker-compose down
# 필요시 SSHFS 재마운트
docker-compose up -d
```

---

### 시나리오 D: 권한 문제

**문제**: Permission denied 에러

**해결**:
```bash
# 1. 파일 권한 확인
ls -la /mnt/nas-music

# 2. 컨테이너 사용자 확인
docker exec music-manager-backend id

# 3. 필요시 권한 수정 (호스트에서)
chmod -R +r /mnt/nas-music
```

## 💡 예방 팁

### 초기 설정 시:

1. **환경변수 확인**
   ```bash
   docker exec music-manager-backend env | grep MUSIC
   ```

2. **자동 스캔 설정** (docker-compose.yml)
   ```yaml
   command: |
     sh -c "
       [ ! -f /app/music_manager.db ] && python scripts/full_setup.py
       uvicorn main:app --host 0.0.0.0 --port 8000 --reload
     "
   ```

3. **헬스 체크 추가**
   ```yaml
   healthcheck:
     test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
     interval: 30s
     timeout: 10s
     retries: 3
   ```
